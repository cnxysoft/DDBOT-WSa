# 登录与资源配置热更新验收报告

日期：2026-11-17。分支：`codex/config-hot-reload`。基于首轮已验收提交 `3fada89` 继续实现。

## 本轮结果

配置更新现在统一经过「校验 → 准备候选资源 → 原子落盘 → 发布快照 → 提交资源」流程。准备或落盘失败不发布版本，并逆序释放已准备的资源。平台登录、代理/图片池、模板与外部数据库、Telegram、WebUI 监听、当前 Bot 协议连接均已接入；普通动态设置继续由消费者读取新快照。

B站、微博 WebUI 重新扫码后可直接应用会话；QQ 官方支持当前协议下的首次绑定、同 AppID 更新凭据。当前覆盖范围内无需为这些操作重启 DDBOT。具体配置字段和生效时机见 [支持矩阵](../config-hot-reload.md)。未知字段仍按需重启处理，不能据此宣称所有任意配置均可在线更新。

## 验收发现与修复闭环

| 问题 | 修复与证据 |
| --- | --- |
| OneBot 候选或回滚异步连接被过早视为成功，可能接到不同账号 | 候选和回滚都等待实际连接并验证身份；真实本地 WS 返回不同 self_id 的原探针复验通过 |
| QQ 更新后可能丢失发送序号、被动回复锚点及映射 | 稳定适配器门面迁移运行状态；真实 HTTP/WS 发送在成功、失败回滚和取消后，msg_seq 连续为 1/2/3/4，鉴权使用正确 Secret |
| 快速重连落在 3 秒监控间隔内，首次 QQ 绑定也可能错过上线事件 | 成功提交后按真实 transport 状态更新在线标记和 ID，再异步发布事件；生产 Config.Save → 事件订阅者再次 Save 的 race 探针连续 10 次通过 |
| 旧 B站/微博响应覆盖新凭据或把新登录状态标为无效 | 请求和健康状态均保留会话代次，迟到结果不能更新新代；阻塞旧 HTTP 后提交新凭据的探针通过 |
| 微博没有 SUB 时自动刷新不能立即引导登录 | 候选阶段支持刷新 API 引导；空凭据模块可运行并在后续更新后恢复 |
| Telegram 命令保存配置等待自身退出而死锁；旧队列在换 token 后继续执行 | 长轮询与串行命令分离；队列携带代次并丢弃旧指令，普通切换不等待正在保存的回调，最终关闭才排空；全包 race 连续 3 次通过 |
| Viper 叶子 override 屏蔽同 section 的其他值，资源比较可能误判无变化 | Set、准备快照和发布快照统一归一化；永久回归验证完整 section、旧快照不变、运行时覆盖在事务前后保持一致 |
| StateManager / EmitQueue 刚启动就停止时 WaitGroup.Add 与 Wait 竞态 | 在启动 worker 前注册计数，同一 worker 内处理重试；立即/并发停止的循环测试通过 race |
| 仅换 WebUI 密码时现有 SSE 仍持有旧授权 | 请求授权时捕获撤权信号，改密码结束 logs/pushes 两路旧流；真实 HTTP 验证 EOF、旧密码拒绝和新密码可用 |
| 监听迁移或自关闭截断保存响应、丢失扫码会话 | 保留同一 Server 与扫码会话，异步退役旧 HTTP server；最终退出同步等待迁移前的请求；真实 HTTP 探针通过 |
| Twitter 旧镜像挑战污染新 Cookie jar、失败预算跨代继承 | 同一请求及挑战固定 runtime 快照；新代提交清空预算，状态写入串行并检查代次；原失败探针复验通过 |
| Twitter 旧恢复验证晚到影响新代，以及成对清空凭据触发 nil panic | 验证客户端固定到旧代，恢复写入前重新验证代次；空凭据生成禁用状态；独立并发与清空回归通过 |
| 退出时主库先于图片池缓存等资源关闭 | 先禁止配置发布、排空事务与命令/服务，再关闭资源和数据库；优先退出钩子与并发保存探针通过 |
| 扩大全包 race 时发现既有 Messenger 重试在关闭后仍运行，以及测试共享状态竞态 | 列表重试使用实例参数、可取消计时器并纳入退出等待；mock 注入和日志缓冲加锁，Twitter 测试恢复回调前排空后台通知；Adapter/Twitter 全包 race 复验通过 |

## 验证

- 根模块：`CGO_ENABLED=0 go test ./... -coverprofile=.coverage.out -timeout 120s` 全量通过。
- `bot` 子模块：`CGO_ENABLED=1 go test -race ./... -timeout 120s` 通过；配置关闭/快照及实际连接集成测试另有独立复验。
- `adapter` 子模块：`CGO_ENABLED=1 go test -race ./... -count=1 -timeout 120s` 全量通过，包含 OneBot、QQ 官方、Satori、Messenger 和门面转发；主代理独立完整复跑通过。
- Twitter 和 admin 全包 race 通过；Twitter 最终后台恢复清理补丁另经独立全包 race 复验。
- 根模块配置、平台、共享资源、WebUI 与事务集成的目标 race 通过。依赖 `modern-go/gls` 的包使用 `-gcflags=github.com/modern-go/gls=-d=checkptr=0`，仅关闭该既有依赖的指针检查，竞态检测保持启用；`bot`、`adapter` 的 race 不使用此选项。
- 本机原生构建：`CGO_ENABLED=1 go build -buildvcs=false -o <TEMP>/ddbot-config-hot-reload.exe ./cmd` 通过。
- 前端语法检查与 `node --test admin/web_tests/config_reload.test.cjs` 的 8 项真实函数行为回归通过。
- `git diff --check` 通过；临时验收文件已改为正式回归，测试产生的未跟踪 B站资源文件在收尾清理。

## 使用边界

1. 在线重连允许同身份凭据和连接参数更新，拒绝跨协议、跨 QQ AppID、QQ 状态文件路径迁移，以及 OneBot/Satori 换账号。迁移应有明确的数据和权限处理流程。
2. 若候选连接失败，程序会尝试恢复原连接。旧服务同时不可用时恢复也可能失败；文件和配置版本未应用不等于旧连接必然在线，可查看日志并重试。
3. 候选登录验证沿用提交前的代理。修复失效代理并更换凭据时，先单独保存代理，再保存凭据。
4. `extDb.path` 切换不迁移数据；旧库文件保留。关闭 extDb 后相应模板函数返回未启用错误或失败值。
5. 本轮使用本地 HTTP/WS 测试服务，没有真实平台账号扫码、真实外部网关连接或浏览器视觉验收证据。

首轮配置监听、基础动态字段、WebUI 状态和前端保存顺序的验收历史见 [首轮报告](config-hot-reload-acceptance-2026-11-17.md)。
