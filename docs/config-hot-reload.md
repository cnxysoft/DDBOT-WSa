# 配置热更新

配置管理器统一处理 WebUI 保存、内部凭据回写和外部文件变更。支持的字段通过格式校验和资源准备后在线应用，包括登录客户端、连接、监听器和共享资源；未列入支持范围的字段仍显示「需重启」。因此不应将当前能力理解为任意配置键都能热更新。

## 生效范围

| 配置 | 生效时机 |
| --- | --- |
| `logLevel`、`ffmpeg.logLevel` | 保存成功时更新日志等级 |
| `bot.commandPrefix`、`customCommandPrefix` | 保存成功时更新；自定义命令保留大小写，空表清空前缀 |
| `cronjob` | 任务实际改变时，全部校验通过后替换；无关保存保持间隔任务的执行时间，已开始执行的任务继续完成 |
| `platform.<site>.enable` | 后续轮询和推送读取新开关 |
| `concern.emitInterval` | EmitQueue 下一次安排计时器时读取 |
| B站、ACFun、抖音、Twitter、Twitch、微博、虎牙、斗鱼、小红书、小黑盒的检测间隔 | 下一次安排计时器时读取；保留平台默认值和随机抖动 |
| `imageMerge.*`、`<site>.imageMerge.*`、`bilibili.imageMergeMode` | 后续图片渲染使用新设置 |
| B站关注策略、专栏/动态解析开关、ACFun 关注策略、Twitter 取消关注与转发全文开关 | 后续对应操作读取新设置 |
| B站、ACFun、抖音、微博、YouTube、小红书、小黑盒、Twitch 的 `onlyOnlineNotify` | 后续通知过滤读取新设置；不清空已有订阅和历史状态 |
| Twitter 翻译开关、目标语言、最小间隔和批次等待时间 | 后续翻译与等待使用新设置；已进行的请求继续完成 |

| `notify.parallel` | 在线调整并发上限；缩小时保留在途许可，后续发送等待空位 |
| B站 Cookie / 账号密码、ACFun 账号与认证信息 | 准备并验证独立候选客户端后替换；旧请求不能覆盖新身份或登录健康状态 |
| 微博 `mode`、`sub`、扫码/自动刷新开关、刷新 API 与 API 地址 | 在线切换访客、登录和 API 模式；空 SUB 配合自动刷新 API 可立即引导登录 |

| `proxy.type`、`localProxyPool.*`、`pyProxyPool.host` | 新代理池准备完成后替换，后续请求读取新池 |
| `imagePool.type`、`localPool.imageDir`、`loliconPool.*` | 在线替换图片池；旧使用者完成后停止 worker 并保存缓存；`loliconPool.proxy` 由后续请求读取 |
| `template.enable`、`extDb.enable/path` | 在线切换模板来源与外部数据库；等待旧数据库操作完成再关闭旧库；关闭模板覆盖时恢复内嵌模板 |
| `telegram.enable/token/endpoint/chats`、命令映射 | 可关闭、启用和换 token；新授权成功后取消旧轮询，丢弃尚未执行的旧代命令；同 token 仅换 chats 不重开轮询 |
| `admin.enable/addr/token` | 先占用候选端口再保存；失败保留原监听；修改密码撤销现有 SSE 授权和扫码任务；仅迁移地址保留扫码会话 |
| 当前协议的 WebSocket 参数、QQ 官方凭据及连接设置 | 稳定适配器门面在线重连，保留事件订阅、标识映射和 QQ 发送序号；身份和协议边界见下文 |
| 小黑盒 `heybox.x_xhh_tokenid` | 后续请求读取新值 |

平台间隔键为 `bilibili.interval`、`acfun.interval`、`douyin.interval`、`twitter.interval`、`twitch.interval`、`weibo.interval`、`huya.interval`、`douyu.interval`、`xhs.interval`、`heybox.interval`。YouTube 通过全局 EmitQueue 间隔调度。

间隔调整不会打断当前请求或正在等待的计时器；当前一轮结束后，下一轮调度采用新间隔。零值使用已有默认/继承逻辑。Twitter 兼容原有的纯数字秒数，其余平台建议使用 `30s`、`2m` 等带单位格式。

## 保存与失败处理

- WebUI 候选配置先通过 YAML、字段类型、日志等级、间隔、图片合并枚举、全部 cron 表达式及目标 ID 校验，再按资源所有者准备候选客户端、数据库和监听器。准备失败返回 HTTP 400，不写文件、不发布新版本。
- 所有候选准备完成后才原子写文件，再发布配置并提交资源切换。任一准备或落盘失败均按逆序清理候选资源；不会先改运行凭据再尝试保存。B站和 QQ 的凭据对在一次事务内写入，只增加一次版本。
- 内部凭据回写通过 YAML 节点定位实际字段，保留其他原文、注释、BOM 和已有换行；落盘前按运行时读取规则验证全部目标值。歧义路径、目标或祖先上的锚点/别名、不适合局部替换的多行凭据及多文档 YAML 明确拒绝，不会报告假成功。
- 外部文件变更无效或文件暂时不可读时，保留上次有效配置，并在状态中显示失败原因；文件修复后自动恢复。
- 文件监听监视父目录，兼容临时文件重命名、删除后重建，100ms 合并连续事件，另有每 2 秒的检查兜底。内容相同的事件不会重复应用。
- 内部写入不再使用忽略窗口。WebUI 返回成功前，配置发布、资源提交及同步回调已完成；状态版本和时间在回调结束后一起更新，保存响应携带此次保存的状态。已开始的旧请求允许完成，不能将结果写回新会话。
- 需要重启的字段保留运行值。将文件改回已运行的值，会清除对应的重启提示。
- 退出时先停止配置监听并排空已接受的事务，拒绝后续发布；再停止 WebUI、Telegram 命令与 Bot 模块，最后保存图片池缓存和关闭数据库。资源清理优先于主数据库的退出钩子。

## 扫码登录与连接边界

- B站、微博 WebUI 重新扫码通过验证并保存后，当前进程直接使用新会话，无需重启 DDBOT。
- 关闭、替换扫码任务或更改管理密码会取消旧会话。取消传播到凭据写入事务；等候写锁或准备资源期间取消，不会继续落盘或发布。持久化已经开始并成功的事务仍完成发布，避免文件与运行状态不一致。微博扫码的出码、轮询和换取登录凭据 HTTP 请求也支持取消。
- QQ 官方在当前 `qqofficial` 协议下支持首次绑定和同 AppID 更新 Secret。未绑定时服务可以继续运行并开放 WebUI；首次成功绑定先预留持久身份，再发布上线事件、启动订阅流程。
- QQ 凭据在其他协议运行时可以保存，但不表示已切换协议。OneBot / Satori 的外部客户端如何扫码登录，仍由对应客户端负责。
- 在线替换拒绝跨协议、跨 QQ AppID、QQ 状态文件路径迁移，以及 OneBot / Satori 连接到不同账号。此类迁移可能改变订阅、权限和 ID 映射，应在独立数据目录或明确迁移流程中完成。
- 连接更新会短暂阻止新发送并等待旧发送结束。候选连接失败会尝试重建原连接；若旧服务此时也不可用，回滚可能失败，错误会记录在日志中，不能保证旧连接始终在线。后续可重试。
- Telegram、Twitter API、Twitch 凭据与全局代理可在同一次保存中更新，候选授权使用新代理；准备期间普通请求继续使用运行中的代理。提交后客户端跟随后续代理更新，不会固定到已退役的池。候选明确关闭代理或没有匹配路由时直连；候选选择失败或取消后不得回退到旧池。其他平台沿用各自已有的请求路由策略。
- 更换 `extDb.path` 不迁移旧数据；原库保留在原路径。关闭外部数据库后，外部数据库模板函数返回未启用错误或对应失败值。

本次协议与平台验收使用真实本地 HTTP / WebSocket 服务模拟成功、失败、超时和并发返回；未使用真实平台账号扫码，也未进行浏览器视觉验收。

## WebUI / API

`GET /api/v1/config` 保持原有的脱敏配置对象结构，展示文件中保存的配置。

`POST /api/v1/config` 的请求格式保持不变，成功响应增加 `reload`：

```json
{
  "status": "success",
  "reload": {
    "revision": 2,
    "appliedAt": "2026-11-17T10:00:00Z",
    "restartRequired": [],
    "watching": true
  }
}
```

新增 `GET /api/v1/config/status` 使用相同鉴权，返回 `reload` 对象的内容；外部重载失败时另有 `lastError`。状态只包含版本、时间、字段路径和错误摘要，不返回凭据值。WebUI 配置页每 5 秒刷新状态，并在保存后立即反馈。

各配置表单和平台开关按用户操作顺序串行保存，失败后后续保存仍可继续。状态和配置读取有请求代次保护，迟到响应不能覆盖本页较新的保存结果；Bot 重启后版本从 1 重新开始仍可正常显示。

配置结构路径与运行时一致，忽略大小写并识别点号形式；源文件和请求先检查歧义，再检查保护规则和合并。`admin.token`、`websocket.token` 的等价拼写都受保护，GET 的凭据脱敏同样覆盖这些拼写和 B站密码。`customCommandPrefix`、`telegram.commands`、`xhs.cookies` 内是数据名称，保留原样；通过嵌套对象提交，不将数据名称中的点号拆成路径。重复等价字段、值与父路径冲突或多文档配置会拒绝保存。

无效 token 的 HTTP 403 带 `X-DDBOT-Auth: invalid-token`，WebUI 据此返回登录页；受保护字段操作的普通 403 保留当前登录。退出或重新登录会废弃旧登录代次，停止旧 SSE 和重连计时器，取消扫码轮询；迟到的登录、配置和扫码响应不能覆盖新会话。已排队但尚未发送的旧配置保存不会使用新 token 继续提交。

仍待完善：保存或扫码成功后的整页配置刷新可能丢失其他未保存草稿；修改管理地址或关闭 WebUI 后尚无完整的迁移导航。慢资源准备期间直接用编辑器修改配置文件，也尚无条件写入冲突检测；外部手工编辑应避免与面板保存并行。这些限制不影响已验收字段的在线应用范围。

## 开发约定

应用代码通过 `Config` 方法访问配置，不能直接读写兼容构造用的 `Config.Viper` 字段。跨多个字段的一次业务操作可先取得 `Snapshot()`，确保读取同一版本。已发布的 Viper 实例不再修改；运行时 `Set` 使用复制后发布。

新增热更新项时，先确认实际消费者会动态读取，或为资源提供明确的更新机制，再加入 `lsp/cfg/reload.go` 的策略与校验。资源型热更新只在全部参与者安装后启用；不能仅把键加入允许列表便宣称支持。

`OnPrepareReload` 接收前后两个有效快照。准备阶段完成所有可能失败的操作，返回不做网络验证的 `commit` 与释放候选的 `abort`；准备函数自己返回错误时也应释放已持有资源。提交过程不得重入配置修改或同步发布会修改配置的事件。稳定门面使消费者无需更换长期持有的资源引用。

同一事务内依赖全局代理验证凭据的资源应使用 `PrepareProxyReloadWithGetter` 返回的候选 getter。准备阶段不切换全局池；提交后 getter 跟随全局池，取消后返回错误。`requests.ProxyOptionWithGetter` 按请求解析路由，传入非空 getter 时严格遵守候选路由；普通 `ProxyOption` 与空 getter 保留原有回退行为。

`OnConfigChange` 回调同步执行并串行化，不得在回调内再次调用 `Set`、`Save`、`Reload`、`MarkApplied` 或配置监听生命周期方法。读取快照是安全的。

可撤销的凭据写入使用 `WriteConfigKeyValuesContext`，底层 `Config.SaveContext` 在取得事务锁后及资源准备完成后检查取消状态。撤销函数只发出取消，不等待扫码工作退出，避免令牌轮换事务与排队的凭据事务相互等待。

主要回归覆盖目录监听连续替换/重建、失败保留、并发快照、运行时覆盖、资源准备与落盘失败回滚、旧请求晚到、短暂重连和首次绑定上线事件、Telegram 命令内保存及旧队列丢弃、WebUI SSE 撤权、资源退出顺序，以及调度器读取新间隔。
